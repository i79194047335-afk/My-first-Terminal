# intrade.bar — карта HTTP API

Восстановлено из HAR-записи живой сессии (2026-08-05) + JS торговой страницы.
Официального API нет; всё ниже — внутренние вызовы фронта, могут измениться
без предупреждения.

**Домен:** рабочее зеркало `intrade35.bar`. Котировки при этом отдаёт
`intrade.bar` — домены смешаны, проверять каждый вызов отдельно.

---

## 1. Авторизация

### Вход
```
POST https://intrade35.bar/login
Content-Type: application/x-www-form-urlencoded

email=<email>&password=<password>&g-rec-res-l=<recaptcha_token>
```

**reCAPTCHA обязательна** — единственное место, где нужен браузер.
При успехе редирект на:

```
GET https://intrade35.bar/auth/id=<user_id>&hash=<user_hash>
```

### Ключевой факт

После входа `user_id` и `user_hash` вшиты в HTML торговой страницы как
JS-переменные:

```js
var user_id = 30169;
var user_hash = "…32 hex…";
```

**Все остальные вызовы авторизуются ТОЛЬКО этими двумя полями формы.
Cookie не требуются** (проверено: заголовка Cookie в запросах нет).

Следствие для бота: браузер нужен один раз, чтобы получить `user_hash`.
Дальше — чистый `requests`.

**Не выяснено:** срок жизни `user_hash`. Проверить: сохранить хеш, через
сутки дёрнуть `balance.php`. Если живёт долго — браузер не нужен вовсе,
хеш кладётся в конфиг.

## 2. Открытие сделки

Подтверждено живыми сделками (демо, USD/JPY, 2026-08-05).

```
POST https://intrade35.bar/ajax5_new.php
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Requested-With: XMLHttpRequest

user_id=30169&user_hash=<hash>&option=USDJPY&investment=2
&time=1&date=0&trade_type=sprint&status=1
```

| Поле | Значение |
|---|---|
| `option` | `USDJPY` — без слэша (в котировках со слэшем!) |
| `investment` | мин 1, макс 700 |
| `time` | минуты, для Sprint input `min=1 max=500` |
| `date` | `0` для Sprint; для Classic — дата закрытия |
| `trade_type` | `sprint` / `classic` |
| `status` | **1 = Call (вверх), 2 = Put (вниз)** |
| `time_value` | в теле ОТСУТСТВУЕТ — только для типа Random |

Для типа Random эндпоинт другой: `ajax_volatility.php`.

### ⚠ Задержка открытия ~3 секунды

**Самый важный факт для минутной экспирации.**

| | запрос отправлен | позиция открыта | `wait` |
|---|---|---|---|
| Call | 18:04:38.3 | 18:04:41 | 3559 мс |
| Put | 18:04:45.9 | 18:04:48 | 2910 мс |

Это НЕ сеть: в той же сессии `balance.php` отвечает за 200–270 мс,
`ajax_percent.php` — за 180 мс. Тормозит именно открытие позиции.

**Цена входа фиксируется в момент ОТКРЫТИЯ, а не запроса.** Экспирация —
ровно 60 с от открытия. Реальное окно сделки:

```
сигнал  →  +3 с (вход по текущей цене)  →  +63 с (расчёт)
```

Задержка плавает (±0.6 с на двух замерах) и от клиента не зависит.
Бэктест обязан моделировать вход по цене «сигнал + 3 с», иначе покажет
эдж, которого в исполнении не будет.

### Ответ при успехе

HTML-строка таблицы (вставляется в `#trade_active`). Всё нужное — в
атрибутах и инлайн-скрипте:

```html
<tr id="trade_inv_224809704" data-id="224809704" data-option="USDJPY"
    data-rate="157.666" data-timeopen="1785953081" data-status="1">
  ...
  <script async>
    time_time_224809704 = 60;
    timer224809704 = setInterval(showRemaining, 1000, "timer_224809704",
                                 60, 224809704, "", 1785953141);
    graph_create_order(224809704, 1, 157.666, "2 $");
  </script>
</tr>
```

| Что | Откуда |
|---|---|
| `trade_id` | `data-id` |
| цена входа | `data-rate` |
| время открытия (unix) | `data-timeopen` |
| время экспирации (unix) | последний аргумент `setInterval` |
| длительность, с | `time_time_<id>` |

Ставка списывается с баланса сразу: 9 361,56 → 9 359,56 при `investment=2`.

### Ошибки

Приходят как plain text вместо HTML:

| Ответ | Значение |
|---|---|
| `''` (пусто) | общая ошибка, фронт показывает «Повторите попытку» |
| `error…` | содержит подстроку `error` |
| `error_time_18` | крайнее время закрытия сделки 18:00 МСК |
| `error_time_night` | ночью торгуется только BTC/USDT |
| `error_time_night_order` | ночная сделка запрещена |

Бот должен проверять эти строки ДО того, как считать сделку открытой.

## 3. Остальные вызовы

Везде `POST`, form-urlencoded, авторизация парой `user_id` + `user_hash`.

| Эндпоинт | Поля | Отдаёт |
|---|---|---|
| `/balance.php` | user_id, user_hash | баланс текстом (`9 363,08 $`) |
| `/ajax_percent.php` | type, time, currency_name, investment, percent, option | текущий процент выплаты числом (`82`) |
| `/trade_check2.php` | user_id, user_hash, trade_id | `invest_close;total_close;total` через `;` |
| `/trade_load_more2.php` | last, user_id, user_hash | история сделок, HTML |
| `/user_real_trade.php` | user_id, user_hash | активные сделки |
| `/deferred/trade_open.php` | (отложенные ордера) | HTML строки сделки |
| `/deferred/trade_check_planned.php` | user_id, data (JSON id) | JSON статусов |
| `/deferred/trade_delete.php` | user_id, user_hash, trade_id | id удалённой |

### Процент выплаты
```
POST https://intrade35.bar/ajax_percent.php
type=Sprint&time=1&currency_name=USD&investment=9&percent=79&option=AUDUSD
→ 82
```
В запрос уходит процент, известный фронту, сервер возвращает **актуальный**
(79 → 82). Выплата плавает — перезапрашивать перед каждой ставкой.

#### Сетка выплат

Со слов владельца (2026-08-05), подтверждена живыми запросами.

| Экспирация | Ставка | Выплата | Безубыточный WR |
|---|---|---|---|
| 1 и 3 мин | < 80 $ | 82% | 54.9% |
| 1 и 3 мин | ≥ 80 $ | 85% | 54.1% |
| 4–500 мин | < 80 $ | 79% | 55.9% |
| 4–500 мин | ≥ 80 $ | 85% | 54.1% |

Порог «5000 рублей» из описания площадки на долларовом счёте означает
ровно **80 долларов, включительно**. Найден перебором с точностью до цента
(USD/JPY, 1 мин): `79.99 → 82%`, `80.00 → 85%`. Владелец подтвердил тем же
значением, проверив вручную.

#### ⚠ Окно у начала часа — выплата 60%

**За 3 минуты до и 3 минуты после начала часа выплата падает до 60%.**
Действует с 17:00 до 09:00 МСК следующего дня.

Это дороже, чем кажется: безубыточный винрейт прыгает с 54.9% до
**62.5%**, то есть порог поднимается на 7.6 пункта. Стратегия с WR 58%
прибыльна в обычное время и убыточна в окне. Шесть минут каждого часа
на протяжении шестнадцати часов — это 96 минут в сутки, 10% всего
времени.

Реализация: [bot/payout.py](bot/payout.py), ограничитель обязан резать
такие входы ДО отправки запроса.

#### Ноль вместо процента

Ночью Classic-экспирации (5, 60 мин) отдают **0%** — так площадка
сообщает «сейчас не торгуется» (ср. `error_time_night`). Ноль надо
трактовать как запрет входа, а не как сбой разбора.

## 4. Данные

### Котировки
```
GET https://intrade.bar/price_now      # ВНИМАНИЕ: домен без "35"
```
Авторизация не нужна. Фронт опрашивает **раз в секунду**.

```json
{
  "AUD/USD": { "Updates": 1785950970, "ask": 0.70529, "bid": 0.70527 },
  ...
}
```
26 пар, включая XAU/USD. `Updates` — unix-время в секундах.

**Формат символов различается:** в котировках со слэшем (`AUD/USD`),
в торговых запросах без (`AUDUSD`). Нужен маппинг.

### Время сервера
```
wss://intrade35.bar/req_info
```
Push-сообщения `{"Time_server": …}`. **Важно для минутной экспирации** —
синхронизация по серверу, а не по локальным часам.

## 5. Что осталось выяснить

1. **Срок жизни `user_hash`** — определяет, нужен ли Playwright постоянно.
   Проверка: сохранить хеш, через сутки дёрнуть `balance.php`.
2. **Расчёт сделки** — `trade_check2.php` в записи не дождались (сессия
   кончилась раньше экспирации). Формат известен из JS:
   `invest_close;total_close;total`, но живьём не подтверждён.
3. **Переключение демо/реал** — счёт всё время демо; как переключает
   фронт, не видно.
4. **Стабильность задержки ~3 с** — два замера (3.56 / 2.91 с). Нужна
   статистика: меняется ли она на волатильности, в сессионные часы, под
   нагрузкой. Это напрямую определяет применимость минутной экспирации.
5. **Рейт-лимиты** — неизвестны, при разработке не долбить.

## 6. Замечания к реализации

- Отдельный процесс, Python 3.10 (как `lighter_feed`), рядом с фидами.
- Ответы — HTML и plain text, не JSON. Парсинг хрупкий: любое изменение
  их вёрстки ломает разбор. Логировать сырой ответ при каждой ошибке.
- Расчёт опциона идёт по цене **брокера** (`price_now`), а не по FXCM.
  Сигнал считается по одному источнику, исход — по другому.
- Переиспользовать `core/news_windows.py` — не торговать в окнах тишины.
- Ограничители обязательны: максимум ставок в день, кулдаун, стоп после
  N убытков подряд.
- Автоматизация почти наверняка против правил площадки. На демо безразлично,
  на реальном счёте — риск блокировки.
